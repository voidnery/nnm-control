# Безопасность NNM-Control

## Как сообщить

Уязвимость или утечка — напрямую владельцу проекта (voidnery), не через issue, не в журнал CI и не в
отчёты. Секрет, попавший в историю git, лечится ротацией (новое значение в окружении), а не записью
в allowlist сканера.

## Что защищено и как

| Что | Как | Где в коде |
|---|---|---|
| Секреты панели | генерирует postinst при первой установке в `/etc/nnm-control/nnm-control.env` (0600, root): `JWT_SECRET`, `SETUP_TOKEN`, `ZABBIX_TOKEN`; обновление их не меняет | `packaging/eterix/debian/postinst`, `packaging/debian/postinst` (старый путь) |
| Первый вход | суперадминистратора создаёт только тот, кто знает `SETUP_TOKEN`; в вывод установки токен **не печатается** — `sudo nnm-control setup-token` | `routes/setup.js`, `packaging/nnm-control-cli` |
| Пароли пользователей | bcrypt; второй фактор TOTP с резервными кодами (bcrypt) | `routes/auth.js`, `services/totp.js` |
| Сессии | JWT с подписью `JWT_SECRET`, срок `JWT_TTL` | `middleware/auth.js` |
| Ключ WMSPanel API, токены серверов | AES-256-GCM, ключ выводится из `JWT_SECRET` (поэтому `JWT_SECRET` нельзя менять — зашифрованные поля станут нечитаемыми); в API не возвращаются | `services/fieldCrypto.js`, `routes/servers.js` |
| Агент на медиасервере | разовый билет на установку, затем токен агента; агент слушает только loopback, панель агентов не набирает (pull) | `routes/agentEnroll.js`, `agent/nnm-agent.mjs` |
| MongoDB | порт не публикуется — только внутренняя сеть стека | `packaging/eterix/compose.yml` |
| Обновления (тонкий пакет) | проверка здоровья только на `127.0.0.1:8580`; хуки и maintainer-скрипты не печатают секретов (upd/0 rev.17 §8.3) | `packaging/eterix/` |
| Репозиторий | gitleaks в CI по всей истории (`.gitleaks.toml`), `.env` и ключи — в `.gitignore`; гейт лицензий зависимостей | `.github/workflows/release.yml`, `ci/` |

## Известные ограничения

- MongoDB без аутентификации: защищена только тем, что не публикуется наружу. Включение
  аутентификации на существующих базах клиентов — отдельная миграция (том создан без пользователей).
- Контейнер backend работает от root и монтирует корень хоста только на чтение (`/:/host:ro`) —
  для метрик дисков хоста.
- Панель публикуется на `APP_PORT` всех интерфейсов по HTTP; HTTPS — nginx хоста или балансировщик.
  Без TLS JWT и пароли идут открытым текстом.
- Ключ шифрования полей выводится из `JWT_SECRET`: утечка `JWT_SECRET` раскрывает и сохранённые
  ключи WMSPanel.
