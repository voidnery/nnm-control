# Начало работы

[English](../en/Getting-started.md) · Русский

## Что нужно

- Машина с Ubuntu/Debian и доступом в интернет (панель работает в Docker; пакет поставит его сам).
- Имя в DNS, которое указывает на эту машину, — им вы будете открывать панель.
- Серверы Nimble Streamer, которыми панель будет управлять. Если они в WMSPanel — ключи WMSPanel API.

## Установка

```bash
wget -qO- https://voidnery.github.io/nnm-control/apt/gpg.key \
  | sudo gpg --dearmor -o /usr/share/keyrings/nnm-control.gpg
echo "deb [signed-by=/usr/share/keyrings/nnm-control.gpg] https://voidnery.github.io/nnm-control/apt stable main" \
  | sudo tee /etc/apt/sources.list.d/nnm-control.list
sudo apt update && sudo apt install nnm-control
```

Установщик спросит:

- **домен панели** — DNS-имя, A-запись которого указывает на машину;
- **порт панели** — по умолчанию `8090`.

Он создаст секреты в `/etc/nnm-control/nnm-control.env` (доступ только root), скачает образы и запустит
панель. Секреты создаются один раз и сохраняются при обновлениях.

> `JWT_SECRET` из этого файла не только подписывает входы, но и шифрует секреты в базе (ключи, токены
> серверов). Не меняйте и не теряйте его: без него зашифрованное не прочитать.

> Есть и второй путь установки — через Eterix DIST-Control (`eterix-updater` со снимком базы и
> автоматическим откатом). Не подключайте оба источника на одной машине.

## Первый вход

1. Узнайте токен установки: `sudo nnm-control setup-token`.
2. Откройте `http://<домен>:<порт>`. Пока суперадмина нет, панель покажет **Первоначальная настройка**.
3. **Токен установки**, **Логин суперадмина**, **Пароль** (не короче 8 символов), подтверждение —
   **Create superadmin**.

После этого токен установки больше ничего не открывает. Суперадмин один; остальных пользователей
заводите на странице **Пользователи** (см. [Доступ](Access.md)). Сразу включите себе двухфакторную
аутентификацию: **Профиль → Настроить 2FA**.

## Подготовка серверов Nimble

На каждом сервере в `/etc/nimble/nimble.conf`:

```
management_listen_interfaces = <IP, на котором панель будет обращаться к серверу>
management_port = 8082
management_token = <длинный случайный токен>
```

затем `sudo service nimble restart`. Через этот «собственный API» панель смотрит состояние сервера, живые
потоки и статистику — без расхода лимита WMSPanel.

> Никогда не открывайте порт управления Nimble в интернет. Только для адреса панели или внутри VPN.

## Подключение WMSPanel

Если серверы управляются через WMSPanel (обычный случай):

1. В WMSPanel: **Control → API setup → Pull API** — включить, скопировать Client ID, создать API key,
   добавить в разрешённые публичный IP панели.
2. В панели: **Система → Настройки → WMSPanel API** — адрес API (`https://api.wmspanel.com/v1` или
   `https://api.wmspanel.ru/v1`), Client ID, API key → **Test connection** покажет видимые серверы.
3. **Control plane → WMSPanel API** → **Save settings**. Панель сразу заберёт список серверов из WMSPanel
   и дальше будет сверять его каждые 10 минут.

**Лимит WMSPanel — 15 000 вызовов в сутки на аккаунт.** Панель расходует их только на изменения и
списки; статистику и проверки она берёт из собственного API Nimble. Остаток за сегодня — на дашборде.
Панель считает только свои вызовы: если аккаунтом WMSPanel пользуется кто-то ещё, реальный остаток
меньше.

Без WMSPanel панель работает в резервном режиме **Native Nimble API**: изменения применяются прямо на
сервере, но временные — пропадают при перезагрузке конфигурации Nimble и не видны в WMSPanel.

## Серверы

Серверы из WMSPanel появляются сами. У каждого откройте **Изменить** и проверьте:

- **Хост** — адрес, по которому панель достаёт до собственного API Nimble;
- **токен управления** — тот, что в `nimble.conf` (без него нет живого состояния и статистики);
- **Адреса воспроизведения** — откуда зрители смотрят (для кнопки «Смотреть» и ссылок);
- **HTTPS-порт** — для LL-HLS.

Подробно — [Серверы и агенты](Servers-and-agents.md). Для плейлистов и логов на сервер нужен агент — там
же, как его поставить.

## Что включить в «Настройках»

По умолчанию выключено то, что создаёт нагрузку:

| Настройка | Зачем | По умолчанию |
|---|---|---|
| **Сбор метрик** | графики по потокам, RTMP Push, SRT и счётчикам серверов | выкл; каждые 10 с, хранится 3 дня |
| **Метрики хоста от агентов** | процессор, память, сеть на дашборде | выкл; каждые 10 с |
| **Сбор логов Nimble** | страница «Логи» | выкл; файл `nimble.log` |
| **Внешний адрес этой панели** | команда установки агента и ссылки на дашборды, если панель за прокси | пусто — берётся из адреса в браузере |

Все разделы сохраняются одной кнопкой **Save settings** внизу страницы.

## Обновление

```bash
sudo apt update && sudo apt upgrade
```

Новые образы скачиваются до перезапуска. Если скачать не удалось — панель не перезапускается и
продолжает работать на старой версии; почините сеть и выполните `sudo systemctl restart nnm-control`.
Перед обновлением полезно сделать резервную копию.

## Обслуживание

```bash
nnm-control status          # состояние служб
nnm-control logs [служба]   # журналы (backend, web, mongo)
nnm-control restart         # перезапуск
nnm-control configure       # заново спросить домен и порт
nnm-control backup          # резервная копия базы (делается и каждую ночь)
nnm-control backups         # список копий
nnm-control restore <файл>  # восстановить — ЗАМЕНЯЕТ текущую базу целиком
nnm-control version
```

- Копии — в `/var/lib/nnm-control/backups`, хранятся 14 последних (не больше 20 ГБ). Копия не
  делается, если на диске меньше свободного места, чем две последние копии.
- `apt remove` оставляет настройки и данные; `apt purge` удаляет настройки, а данные (тома Docker
  `nnm-control_mongo_data`, `nnm-control_media_spool`, `nnm-control_geoip_db`) остаются, пока их не
  удалить вручную.
