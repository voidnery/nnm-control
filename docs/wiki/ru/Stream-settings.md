# Потоки: настройки, транскодеры, категории, функции

[English](../en/Stream-settings.md) · Русский

## Где живут настройки потоков

В режиме WMSPanel настройки потоков (UDP/SRT-выходы, входы MPEG-TS, RTMP Pull и Push, hot swap,
приложения) хранятся в WMSPanel. Панель читает и пишет их через WMSPanel API — на вкладках
[страницы сервера](Servers-and-agents.md#страница-сервера), в функциях, категориях и через
[API](API.md#настройки-потоков). Nimble получает изменения на ближайшем цикле синхронизации WMSPanel —
примерно через 30 секунд.

Каждое изменение — событие `stream_object.*` (см. [События и реакции](Events-and-reactions.md)).

## Транскодеры

**Вещание → Транскодеры** (смотреть — `wmsobjects.view`, действия — `wmsobjects.manage`; только в режиме
WMSPanel).

- **Создать транскодер из панели нельзя**: в API WMSPanel нет такого метода. Создайте его в WMSPanel,
  здесь — смотреть, клонировать и править.
- **Пауза**, **Возобновить**, **Клонировать** (копия создаётся на паузе), правка, удаление (сценарии
  удаляются безвозвратно). Пауза и возобновление — и группой.
- Массового перезапуска нет намеренно — для этого есть [функции](#функции).
- Состояние: идёт, частично, нет выхода, на паузе, неизвестно.
- **Обновить состав сценариев** тратит вызовы WMSPanel API.

## Объекты WMSPanel

**Инфраструктура → Объекты WMSPanel** — настройки уровня аккаунта, применяются к отмеченным серверам:

- **ABR** — лестницы качеств;
- **алиасы** приложений (по умолчанию для HTTP, RTMP, RTSP, SRT);
- **origin-приложения** — переводят приложение в режим HTTP Origin. Такой edge не кэширует — на
  странице раздачи это видно как препятствие.

## Категории

**Инфраструктура → Категории** (`category.view` / `category.manage`) — именованные группы потоков с
разных серверов, чтобы управлять ими разом. Входят: SRT Out, SRT in Nimble, SRT In, RTMP Pull,
RTMP Push, Hotswap.

1. **Новая категория**.
2. **Добавить потоки**: сервер и вид → **Загрузить объекты** → отметить.
3. У каждого потока видно состояние: работает, остановлен, не найден на сервере.

Действия — **Запустить**, **Остановить**, **Перезапустить** — над отмеченными потоками, а если ничего не
отмечено — над всеми, с подтверждением. Перезапуск есть только там, где он есть в WMSPanel (SRT in
Nimble, RTMP Push, RTMP Pull); для остальных используйте функцию «остановить — подождать — запустить».
Результат может быть частичным — по каждому потоку видно, что вышло. Всё записывается в аудит.

## Функции

**Вещание → Функции** — инженерные макросы: последовательность шагов над потоками WMSPanel с проверкой
результата и автоматическим откатом. Создавать — `functions.manage`, запускать — `functions.execute`
(своя роль может запускать только назначенные ей функции). Только в режиме WMSPanel.

### Собрать

1. **Новая функция** → **Добавить шаг**:
   - изменение (поля объекта);
   - пауза, возобновление, перезапуск;
   - ожидание;
   - готовые шаги: переключить видео/аудио-источник SRT in Nimble, переключить адрес RTMP Push.
2. **Варианты исполнения** — те же шаги с разными значениями (например, «основной» и «резерв»).
   Функцию с вариантами запускают, выбрав вариант.

### Что происходит при запуске

1. **Предпроверка**: сервер привязан, объект существует, изменяемые поля есть. Если нет — ничего не
   меняется.
2. Каждый шаг: снимок → изменение → **проверка**, что Nimble действительно применил (опрос каждые 5 с,
   до 180 с — WMSPanel доставляет изменения циклами примерно по 30 с). Для SRT in Nimble — ещё и
   состояние «synced».
3. Перезапуск там, где WMSPanel его не умеет, делается как «остановить — подержать — запустить»;
   по умолчанию держать 40 с (**Держать остановленным (секунд)**). Слишком короткая пауза может
   схлопнуться, и поток так и не остановится.
4. **Если шаг не удался — все сделанные шаги откатываются в обратном порядке.** Итог: откачено или «откат
   не удался». Перезапуск и ожидание откатить нельзя.

**История запусков** — последние 50, с живым ходом выполнения. **Убрать запуски старше 3 дней** не трогает
идущие.
