# Плейлисты

[English](../en/Playlists.md) · Русский

Серверный плейлист Nimble (Nimble Playout) превращает файлы MP4/MP3 на сервере в выходной поток по
расписанию. В панели плейлист собирают в редакторе, хранят, проверяют и записывают на сервер — без
ручной правки JSON.

Права: `playlist.view` — смотреть; `playlist.manage` — создавать, менять, удалять, разворачивать,
останавливать и запускать потоки, откатывать, загружать и удалять медиафайлы. Для записи на сервер
нужен [агент](Servers-and-agents.md#агент-на-сервере).

## Как устроен плейлист

**Задача → Блоки → Источники.**

- **Задача** — один выходной поток `приложение/поток` (например, `live/news`). `InactivityTimeout` —
  через сколько секунд без данных поток считается остановленным (у Nimble по умолчанию 30; 0 — никогда).
- **Блок** — кусок эфира: `Id`, название, `Start` (время GMT `ГГГГ-ММ-ДД ЧЧ:ММ:СС`), `Duration`,
  `TotalDuration`, `MaxIterations`, источник по умолчанию.
- **Источник** — файл (`vod`) или живой поток (`live`): путь, смещение начала, длительность, названия
  для Icecast, субтитры, метки SCTE-35.

Две вещи, на которых обычно спотыкаются:

1. **`MaxIterations`.** У Nimble по умолчанию блок играет **один раз**, а потом поток остаётся в эфире
   пустым. `0` — бесконечно по кругу. Новые блоки в панели создаются с `0`; если у блока нет ни
   `MaxIterations`, ни `TotalDuration`, редактор предупредит.
2. **Только MP4 и MP3.** `.mov`, `.mkv`, `.ts` Nimble Playout не играет. Перепаковать без перекодирования:
   `ffmpeg -i file.mov -c copy -movflags +faststart file.mp4`.

## Создать плейлист

1. **Вещание → Плейлисты → Новый плейлист**, название обязательно.
2. **Сверять с сервером** — по желанию: редактор будет отмечать файлы, которых на этом сервере нет, и
   предлагать файлы с сервера на выбор.
3. Добавить задачу, в неё блок, в блок источники.
4. **Вставить рекламу** — по желанию: выбранные файлы встанут перед каждым N-м элементом. Повторное
   применение заменяет прошлую вставку.
5. **Сохранить.** Сохранённый плейлист ни на что не влияет, пока его не развернули.

Есть **Импорт JSON**, **Показать JSON** и **Скачать** — для переноса и проверки.

## Загрузить медиа

На сервере, в панели **На сервере**, — **Загрузить файл**. Файл сначала принимается панелью, затем агент
забирает его в фоне (до 12 часов; пока панель хранит файл, можно **Повторить**). Место на диске
проверяется заранее.

Удалить файл нельзя, пока на него ссылается любой плейлист в каталоге конфигурации этого сервера, —
иначе эта запись заиграет тишиной.

## Развернуть на сервер

**Выгрузить** → сервер → имя файла в каталоге конфигурации Nimble.

> По умолчанию — `server_playlist.json` (через подчёркивание): его читает Nimble. Если на сервере файл
> называется иначе, панель «На сервере» покажет, какие файлы там есть, — выберите нужный. Запись в файл,
> который Nimble не читает, ничего не изменит в эфире.

Что делает панель при записи:

- пишет **чистый файл** — без служебных полей редактора и пустых значений;
- **обновляет `Id` изменённых блоков.** Nimble не перечитывает блок, у которого `Id` не изменился, —
  даже если поменялось содержимое. Панель сравнивает с тем, что уже лежит на сервере: блок с тем же
  `Id`, но другим содержимым, без `Id` или с повторяющимся `Id` получает новый. Неизменённые блоки
  сохраняют `Id` и не перезапускаются;
- сохраняет прежнюю версию — в истории панели и как `.bak` на сервере.

После записи панель сообщит, сколько блоков получили новый `Id` и какие блоки сыграют один раз.

### Когда панель откажется писать

| Причина | Можно ли «всё равно» |
|---|---|
| файл не разбирается (испорчен) | нет, никогда |
| агент на сервере выключен | нет — сначала включите агента |
| часть файлов на сервере отсутствует — эти записи сыграют тишину | да (если файл вот-вот появится) |
| не удалось прочитать список медиа на сервере — проверить нечем | да |
| есть источники не MP4/MP3 | да, но Nimble их не сыграет |
| плейлист пустой — запись остановит все потоки плейлиста на сервере | да, если так и задумано |

«Всё равно записать» — `force` в [API](API.md#плейлисты); остановка потока (ниже) делает это сама.

## На сервере

Панель **На сервере** (на странице плейлистов) показывает, что реально лежит и играет на выбранном
сервере:

- текущий плейлист и найден ли файл (если нет — какие файлы есть рядом: частая причина — имя на один
  символ отличается);
- медиафайлы: каких нет (`missing`) и какие проверить нельзя — лежат вне каталога, доступного агенту
  (`unverifiable`, это не то же самое, что «нет»);
- **предупреждение о расхождении**: файл изменили после последней записи из панели — следующая запись
  эту правку перезапишет;
- подсказки: зацикливается поток или закончится и когда; стыки, на которых меняется разрешение, частота
  кадров, кодек, частота дискретизации или число каналов звука — на таких стыках плееры спотыкаются.

### Остановить и запустить поток

- **Остановить** — задача убирается из файла, файл записывается заново. Остальные потоки не трогаются.
- **Остановленные потоки** — список собран из истории последних 50 версий:
  - **Запустить сначала** — с начала блока;
  - **Продолжить с места остановки** — примерно с того места, где остановили (оценка по времени записей
    и длительностям файлов, с откатом на 3 секунды). Не получится, если длительность какого-то файла
    неизвестна.

Оба действия — обычная запись со всеми проверками.

### История и откат

**История выкладок** — каждая запись: кто, когда, с отметками «принудительно» и «файлов не хватало».
**Откатить** — записывает выбранную версию заново, через те же проверки.

**Импортировать в панель** — забрать плейлист с сервера в редактор как черновик.

## События

Запись, остановка и запуск потока — события `playlist.deployed`, `playlist.stream_stopped`,
`playlist.stream_started` (см. [События и реакции](Events-and-reactions.md)). В `playlist.deployed`
есть `renewed_ids`, `plays_once` и `unsupported` — то же, что панель показала оператору.
