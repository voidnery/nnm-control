# Серверы и агенты

[English](../en/Servers-and-agents.md) · Русский

## Серверы

**Вещание → Серверы.** Смотреть — `servers.view`; добавлять, менять, удалять, менять порядок —
`servers.manage`.

### Откуда берутся

В режиме WMSPanel панель сама забирает серверы Nimble из WMSPanel: через 15 секунд после запуска и
затем каждые 10 минут (кнопка **Sync now** — немедленно). Сопоставление — по идентификатору WMSPanel.

- Название, теги, состояние и домены обновляются при каждой синхронизации.
- **Хост** заполняется, только если он пустой, — исправленный вами адрес не перезаписывается.
- Новому серверу ставится порт управления 8082 и пустой токен — задайте токен из `nimble.conf`, иначе
  не будет живого состояния и статистики.
- Сервер, пропавший из WMSPanel, из панели **не удаляется**.

### Добавить или изменить

**+ Добавить сервер**:

- **Для чего эта машина** — первым, от этого зависят остальные поля:
  - **Медиасервер Nimble**;
  - **Медиасервер и узел сети раздачи** — для [раздачи](Distribution-and-LL-HLS.md);
  - **Edge-proxy — раздача без Nimble** — шлюз; у него нет привязки к WMSPanel и портов Nimble.
- **Название**, **Хост (IP или DNS)** — адрес, по которому панель обращается к собственному API Nimble.
- **Порт и токен управления** — из `nimble.conf` (порт по умолчанию 8082). При правке пустое поле токена
  оставляет прежний.
- **Сервер WMSPanel** — привязка. Без неё настройки потоков, функции и категории для сервера недоступны.
- **Теги** — через запятую.
- **Адреса воспроизведения** — по каким адресам зрители смотрят: подпись, хост, порт HLS (8081),
  порт RTMP (1935), SSL. Нужны для кнопки «Смотреть», ссылок и проверки сертификатов.
- **HTTP-порт** Nimble (по умолчанию 8081) — ни один API его не сообщает, поэтому его задаёт оператор.
- **HTTPS-порт** — пусто = 443; нужен для LL-HLS. **Проверить TLS** — после сохранения.

Удаление сервера убирает его **только из панели**; на самом сервере и в WMSPanel ничего не меняется.

### Страница сервера

Набор вкладок зависит от режима управления.

**Режим WMSPanel** (смотреть — `wmsobjects.view`, менять — `wmsobjects.manage`; сервер должен быть
привязан к WMSPanel):

| Вкладка | Что это |
|---|---|
| Streams | живые потоки |
| Apps, Interfaces | live-приложения и RTMP-интерфейсы |
| RTMP Pull | затягивание потоков (live pull), с резервными адресами; перезапуск |
| RTMP Push | republish — отправка потока дальше (`republish.view` / `republish.manage`) |
| SRT In | входы MPEG-TS/SRT |
| SRT Out | UDP/SRT-выходы |
| SRT in Nimble | исходящие MPEG-TS: пауза, возобновление, перезапуск |
| Hotswap | горячая подмена источника |
| Charts | графики (`streams.view`) |

Изменения пишутся в WMSPanel и доходят до Nimble за его цикл синхронизации — около 30 секунд.

**Резервный режим Native Nimble API**: Streams (каждые 10 с), Sessions (каждые 15 с; **Disconnect
selected** — `sessions.manage`), SRT (только чтение), MPEG-TS, Playout, Control (**Перезагрузить
конфиг**, **Перезагрузить SSL**, **Синхронизировать WMSPanel** — `control.manage`). Изменения в этом
режиме временные: пропадают при перезагрузке конфигурации и видны только на этом сервере.

### Графики

Вкладка **Charts** — история за 15 мин … 72 ч, **Всё сразу** или **Один поток**, **Живой режим**.
Нужно включить **Сбор метрик** в настройках (по умолчанию каждые 10 с, хранится 3 дня). Растущие
счётчики рисуются как скорость в секунду.

**Почему нет данных?** объясняет по каждому источнику: «пусто» — у сервера действительно нет такого;
красная строка — панель не смогла спросить (проверьте адрес и токен управления).

## Агент на сервере

Агент — небольшая служба на сервере, которая работает с его файлами: пишет плейлисты и конфиги,
принимает медиафайлы, отдаёт логи Nimble. Он **необязателен**: всё остальное работает без него.

Агент сам обращается к панели (раз в ~25 секунд ждёт задачу); панель к нему не подключается, поэтому
он работает и за NAT. Nimble агент не трогает.

Права: смотреть — `servers.view`; ставить, обновлять, удалять — `servers.manage`.

### Установить командой

1. **Инфраструктура → Агенты** → у сервера **Установить агент**.
2. **Я выполню команду сам**.
3. **Адрес, по которому СЕРВЕР будет обращаться к этой панели** — подставлен из браузера; исправьте,
   если серверы это имя не разрешают или сертификат на нём не тот. (Постоянно — **Внешний адрес этой
   панели** в настройках.)
4. Каталог логов Nimble (по умолчанию `/var/log/nimble`).
5. **Выдать команду установки** и выполнить её на сервере от root. Вариант **С проверкой** сверяет
   скрипт по SHA-256 перед запуском — рекомендуется.

Ход видно на странице: тикет выдан → сервер скачал установщик → агент зарегистрировался.

- Тикет одноразовый и действует 30 минут. Новый тикет отменяет прежний неиспользованный.
- Установщику нужны root, `curl` и Node.js 18+. Токен агента создаётся на самом сервере.
- Если панель открыта по `http://`, токен уйдёт открытым текстом — установщик предупредит.

### Установить по SSH

**Панель поставит по SSH** → **Прочитать ключ хоста**, сверить отпечаток → пароль или закрытый ключ
(можно с sudo) → **Установить**. Учётные данные нигде не сохраняются — ни в базе, ни на диске, ни в
аудите. Если ключ хоста изменился, установка останавливается до отправки пароля.

### Привилегированный помощник

Отдельная служба с правами root для машин сети раздачи и шлюзов: ставит пакеты, выпускает сертификаты,
пишет конфиги nginx/Nimble. Может запускать только шесть названных программ (`apt-get`, `certbot`,
`nginx`, `systemctl`, `ln`, `rm`) и писать только в свои каталоги. **Установить помощника** — после
настройки агента; скрипт показывается, запускаете его вы.

### Если агент молчит

| Сообщение | Что значит | Что делать |
|---|---|---|
| Агент ни разу не выходил на связь | установка не закончена или агент не достаёт до панели | `journalctl -u nnm-agent -n 50` |
| Агент перестал опрашивать панель | последняя связь больше 70 с назад | `systemctl status nnm-agent` |
| Агент перезапускается по кругу | 3 и больше перезапуска за 10 минут | `journalctl -u nnm-agent -n 200` |
| Агент забрал работу и не ответил | одна операция зависла; так выглядит и большая загрузка по медленному каналу | подождать или проверить канал |
| Панель не выдала задачу агенту | ошибка **панели** | сообщите разработчику: сервер и время |
| Агент опрашивает панель штатно | всё в порядке | — |

Сторож проверяет агентов каждые 30 секунд и записывает перемену, только если она повторилась 3 раза
подряд (~90 с) — мигание не шумит. Отсюда события `agent.offline` и `agent.online`. **Сам сторож ничего
не перезапускает.**

**Центр агентов**: сколько агентов с проблемами и устаревших; **Обновить все отстающие** (обновление
получают только те, что на связи; агент сверяет контрольную сумму); **Пинг**; **Восстановить** —
перезапуск по SSH со сбором журнала.

**Сетевые интерфейсы для графиков** — какие интерфейсы рисовать на дашборде (ничего не отмечено — все
физические).
