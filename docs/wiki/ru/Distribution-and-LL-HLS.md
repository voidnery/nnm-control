# Раздача и LL-HLS

[English](../en/Distribution-and-LL-HLS.md) · Русский

## Раздача

**Вещание → Раздача** — сети раздачи: кто у кого берёт поток, что раздаётся и по каким ссылкам смотреть.
Пункт меню виден с правом `wmsobjects.view` в режиме WMSPanel; работа с сетями требует `cdn.view`
(смотреть) и `cdn.manage` (менять) — нужны оба.

Разделы: **Каналы** (открывается первым), **Сеть раздачи**, **География**.

### Сеть и роли узлов

**Новая сеть** → **Добавить сервер…** → роль и **Берёт контент с**:

| Роль | Откуда может брать |
|---|---|
| Приём (ingest) | ниоткуда |
| Origin | с приёма |
| Промежуточный (mid) | с origin |
| Edge | с origin или промежуточного |
| Шлюз (gateway) | ниоткуда — направляет зрителей на edge |

Сохранение отклоняется при неверной роли, повторе сервера, ссылке на себя, недопустимом источнике или
цикле; узел без источника сохраняется с предупреждением. Удаление сети серверы не трогает.

### Настройка на серверах

На вкладке **Настройка** три шага: **1 · Что раздаём**, **2 · Настройка на серверах**, **3 · Доходит ли**.

1. **Приложения, которые несёт эта сеть** — маршрут Nimble задаётся на приложение целиком, поэтому
   раздаются все потоки приложения.
2. **Показать план** — какие маршруты будут созданы на каждом edge (`/app/` → `origin:port/app/`).
   **Применить** создаёт и правит маршруты в WMSPanel, каждый перечитывает; при сбое откатывает только
   созданные в этом запуске.
3. **Применить никогда не удаляет маршруты.** Выключенное приложение продолжит раздаваться, пока
   маршрут не удалить вручную (**Уже записано в WMSPanel**).

План не применится, если приложение на edge в режиме HTTP Origin (edge не кэширует), у edge нет
привязки к WMSPanel или источника. Проверить нужно, если HTTP-порт origin не задан (предполагается
8081) или у узла несколько источников (используется первый).

### Доходит ли

- **Проверить состояние** — читает живые потоки с каждого узла (через агента или напрямую, без расхода
  WMSPanel): идёт, в покое (маршрут есть, зрителей нет — это нормально), маршрута нет, ещё ничего не
  публикуется, узел не ответил.
- **Проверить как зритель** — запрашивает плейлист у каждого узла как плеер и через несколько секунд ещё
  раз, чтобы увидеть, движется ли он: «да, и поток идёт», «отдаёт застывший плейлист», «маршрута нет
  (404)», «отказано (403)», «origin не ответил (5xx)», «таймаут», «недоступен».

### Наблюдение за каналами

**Проверять самим, каждые N мин** (по умолчанию выключено; 5 … 1440 мин, `cdn.manage`). Проверяются
включённые каналы сетей с наблюдением, на каждом edge — как зритель; edge с агентом новой версии
проверяется ещё и изнутри, чтобы отличить «не отдаёт» от «не достать».

Канал **здоров**, если проверен хотя бы один edge и все проверенные ответили нормально. Если сама панель
не смогла проверить — ничего не записывается и это не считается сбоем. При смене состояния — события
`channel.unhealthy` / `channel.healthy`; первая проверка с плохим результатом тоже даёт событие.

История: доступность за час, сутки, неделю, последние 24 проверки по каналу, самый медленный ответ.

### Каналы и ссылки

**Добавить канал** — приложение и поток (потом не меняются), боевой или тестовый, что отдаём зрителю:
HLS, LL-HLS (ссылка появится, когда на edge подтверждены TLS и HTTP/2), DASH. Потоки, которые уже идут на
origin, но каналом не стали, перечислены — щелчок заполняет новый канал.

- **Боевая ссылка** — через шлюз; видно, на какой edge она ведёт сейчас.
- **Тестовые ссылки** — прямо на каждый edge.

**Кто может смотреть**: все; по ссылке с токеном (по умолчанию 20 мин, можно привязать к IP зрителя);
с наших сайтов; по странам; по диапазонам IP. Защита действует после **Записать защиту** на сети.
**Сменить ключ** — все выданные ссылки перестают работать.

**Повтор из архива** — ссылки на запись (сама запись включается в WMSPanel).

### Шлюз

Режимы: **Прямо на edge** (по умолчанию), **Redirect-шлюз** (ответ 302), **Proxy-шлюз**. Шлюзу нужен
агент и помощник. Выбор edge: **Ближайший** (нужны координаты и база географии), **Наименее
загруженный**, **По весу**, **По порядку**. **Если ни один edge не жив**: отказать (по умолчанию) или
отправить на origin. **Посчитать** показывает решение, никого никуда не отправляя.

Сохранение сети само переписывает nginx шлюза; если не вышло — панель скажет почему (нет помощника,
шлюз не подготовлен, у edge нет адреса).

### География

Офлайн-база DB-IP: **Скачать / обновить** (версия Country — без координат, City — с координатами, в ~15
раз больше). **Определить** / **Определить все** — координаты узлов; введённое вручную не
перезаписывается.

## LL-HLS

**Вещание → LL-HLS** — включение Low-Latency HLS на edge. Смотреть — `servers.view`; план, запись, откат,
включение на приложении — `servers.manage`.

LL-HLS работает, только если верно всё четыре:

1. на машине есть привилегированный помощник;
2. есть сертификат, и у него не вышел срок;
3. TLS отвечает с HTTP/2 (ALPN h2) и сертификатом, который примет плеер;
4. в плейлисте есть части (parts).

Если не хватает только частей — плеер молча получит обычный HLS, и никто об этом не узнает. Поэтому
панель проверяет и это.

### Сертификат

Оценивается по тому, что сервер реально отдаёт при TLS-рукопожатии, а не по файлам:

| Состояние | Что делать |
|---|---|
| Сертификат работает | ничего |
| Скоро истекает (20 дней и меньше) | перевыпустить |
| Истёк | перевыпустить |
| Плеер отвергнет (нет промежуточного, самоподписанный) | перевыпустить |
| Не покрывает имя | сменить домен — перевыпуск даст то же |
| Прописан, но на TLS-порту никто не ответил | проверить Nimble и порт |
| Не настроен | выпустить |

Истекающие сертификаты имён, по которым зрители ходят по HTTPS, панель сообщает и событием
`certificate.expiring` — см. [События и реакции](Events-and-reactions.md).

### Транспорт

1. Домен (DNS уже должен указывать на машину), **TLS-порт** (по умолчанию 8443).
2. Способ:
   - Let's Encrypt через порт 80 — продлевается сам, порт 80 должен быть доступен из интернета;
   - Let's Encrypt через DNS-запись — продлевается сам, нужен токен API DNS-провайдера; единственный
     способ получить wildcard;
   - **Сертификат, который у вас есть** — вставить цепочку и ключ; сам не продлевается. Сюда же
     сертификаты Минцифры (Apple и Chrome им не доверяют).
3. **Показать, что будет записано** — разница в `nimble.conf`, секреты скрыты.
4. **Записать и перезапустить Nimble** — фоновая работа до 15 минут с журналом. Перезапуск Nimble
   обрывает сессии зрителей. Готово, только если TLS-проверка после записи подтвердила HTTP/2. Если
   `nimble.conf` изменили после предпросмотра — отказ.
5. **Вернуть как было** — из резервных копий.

### Приложения

**Включить** LL-HLS на приложении edge: размер части не меньше 500 мс и не больше половины чанка (значения
вне диапазона отклоняются, а не подгоняются). Нужен контейнер HLS; «заодно перевести контейнер на fMP4»
**убирает обычный HLS**. После включения **нужно перезапустить входной поток**, иначе для зрителей ничего
не изменится. **Спросить линию** — проверить части на конкретном потоке.
